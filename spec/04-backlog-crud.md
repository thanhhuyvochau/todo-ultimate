# Backlog CRUD

## Overview
Full Create, Read, Update, Delete operations for tasks in the Backlog. This is the core data entry point — every task starts here unless auto-generated by a recurring rule or manually placed in Today.

## Requirements
- Create tasks with: `title`, `description` (Markdown), `priority` (`low`/`medium`/`high`), `estimated_minutes`.
- Read tasks filtered by status, priority, or search query.
- Update any task field individually (partial updates).
- Delete tasks (soft-delete preferred, or hard-delete with confirmation).
- Every new task defaults to `status: 'todo'` and assigned to Backlog.
- Task ID generated via UUID (crypto.randomUUID()).

## Data Validation
- `title`: required, 1–200 characters, trimmed.
- `priority`: must be `low`, `medium`, or `high`.
- `estimated_minutes`: required, positive integer, max 1440 (24 hours).
- `description`: optional, max 100,000 characters.

## IPC Channels
| Channel | Request | Response |
|---------|---------|----------|
| `tasks:getAll` | `{ status?: TaskStatus, priority?: Priority }` | `Task[]` |
| `tasks:create` | `Omit<Task, 'id' \| 'created_at' \| 'updated_at'>` | `Task` |
| `tasks:update` | `Partial<Task> & { id: string }` | `Task` |
| `tasks:delete` | `{ id: string }` | `{ success: boolean }` |

## UI Behavior
- Backlog panel lists all tasks with `status: 'todo'`.
- Sort options: by priority, by created date, by title.
- Color-coded priority badges: red (high), yellow (medium), gray (low).
- Inline edit: click title/pencil icon to quick-edit.
- Confirmation dialog on delete.

## Error Handling
- Validation failure → return `IpcResult` with `VALIDATION_ERROR` code and field-level messages.
- DB write failure → `DB_WRITE_FAILED`.
- Task not found on update/delete → `NOT_FOUND`.

## Dependencies
